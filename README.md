# Pid — 直流电机速度闭环

STM32F103C8T6 + TB6612 + JGB37-520 编码器电机。5 ms 控制周期、20 kHz PWM。
目标：阶跃响应 **< 50 ms**、静差 **< 5%**、扰动后能回目标。

**当前状态（2026-10-22）**：**闭环调参完成 + 自动调参工具就位**。编码器已接（TIM3 / PA6-PA7），
5 ms 中断里跑「测速 → PID → 前馈 + 限幅 → PWM」。参数由自动调参得出并固化：
**Kv=4.15、Kp=14.0、Ki=5、Kd=0、限幅 ±1000‰**，另有"稳态 P 项死区"抑制量化极限环。
实测（各 4 次）：**80 rpm 上升 33~39 ms、200 rpm 76~78 ms、静差 −0.3~−1.9%**。
调参过程与全部测量坑见 `../notes/tuning-log.md`；自己复测用 `pidtune verify`。

> 逐脚接线：`../docs/wiring-plan.md`　｜　配置/接口/踩坑全表：`../AGENTS.md`　｜　考核动作：`../docs/acceptance.md`
> **看数据 / 排错查表：§9「信息从哪来」**　｜　**PID 原理 & 为什么这么写：§10**

## 1. 现在怎么用

烧录后串口（115200）敲：

| 命令 | 作用 |
|---|---|
| `S200` | 目标 200 rpm（负号=反转，限幅 ±333）|
| `X` | 急停 |
| `A` | 开/关自动阶跃（打开后：2 s → 150 rpm 保持 3 s → 回 0，10 s 循环。**上电默认关**）|
| `V` | 开/关 **VOFA 波形流**（打开后串口是二进制帧，文本终端看起来就是乱码）|
| `C` | **进/出编码器标定模式**：PWM 强制 0，只累计计数（手转输出轴 10 圈看总数）|
| `KP12.5`<br>`KI3`<br>`KD0.05`<br>`KV4.15` | **实时改增益 / 前馈**（给 VOFA+ 滑块、自动调参用）。支持小数，大小写都收。硬钳位：Kp≤100、Ki≤200、Kd≤50、Kv≤20 |
| `?` | 回一行 `tgt act out kp ki kd kv tick rx err f`（`f`=故障码：0 正常 / 1 ENC_DIR / 2 NO_PULSE / 3 STALL）|

命令带不带换行都行：带 `\n`/`\r` 立即执行；**不带给也行 —— 停顿 500 ms 自动结算**
（`CMD_FLUSH_TIMEOUT_MS`，在 `App/cmd/cmd.h` 可改）。

⚠️ 串口工具的"行尾"设置有个坑：VS Code 串口监视器的 `vscode-serial-monitor.lineEnding`
枚举值是 **转义序列本身**（`"\n"` / `"\r"` / `"\r\n"`），写成描述文字 `"LF"` 会把
**字母 L 和 F 当成正文发出去**，于是 `S50` 变成 `S50LF` → 被解析器判为非法行 → 目标不动。

OLED 四行：目标 / 实际 / 输出‰ / 参数（有故障时显示 `FAULT xxx`）。
VOFA+ 用 JustFloat，三条线 = 目标、实际、输出。**波形流上电默认开启**（敲 `V` 可关），
所以平时串口是纯文本；看到满屏乱码先确认是不是自己开了 `V`，再怀疑波特率。

### 用 VOFA+ 滑块实时调参（不重烧）

固件已支持 `KP/KI/KD` 串口命令，配上 VOFA+ 的滑块就能**边拖边看波形**：

```
VOFA+ 左侧「控件」→ 拖 3 个 Slider 到图形区 → 分别改名 Kp / Ki / Kd
左侧「命令」→ 新增 3 条命令，内容填：
    Kp →  KP%f      Ki →  KI%f      Kd →  KD%f        （行尾选 \n）
然后滑块分别绑定到对应命令
```

| 滑块 | 命令 | 建议范围 | 步长 | 固件钳位上限 |
|---|---|---|---|---|
| Kp | `KP%f` | 0 ~ 30 | 0.5 | 100 |
| Ki | `KI%f` | 0 ~ 30 | 0.5 | 200 |
| Kd | `KD%f` | 0 ~ 2 | 0.05 | 50 |

**验证生效**：拖一下 Kp，OLED 第 4 行的 `KP` 数字会**立刻**跟着变（5 ms 内）。

> 本项目**不需要包尾字符**（很多教程里写的 `KP%fM` 那个 `M` 是多余的）——
> 靠行尾 `\n` 结算，就算 VOFA 不发换行，停 500 ms 也会自动结算。
>
> ⚠️ **调好后必须把数值写回 `speed-loop.h` 的宏**，否则复位就回到宏初值。
> ⚠️ 拖滑块时串口会穿插命令，不影响波形帧（接收是中断、发送是主循环）。

**没有电机也能验**：PA8 接 `1 kΩ + LED → GND`，`S100`/`S300` 看亮度变化。

### 闭环三步走（按顺序，每步都有判据）

| 步 | 做什么 | 操作 | 判据 |
|---|---|---|---|
| **1 标定** | 验证 1320 计数/圈是不是真的 | 发 `C` → **手转输出轴正好 10 圈** → 发 `?` | `enc≈13200`、`revx10≈100`（±2%）。差得多就改 `-DMOTOR_ENC_PPR` / `-DMOTOR_ENC_GEAR_RATIO` 重烧 |
| **2 方向** | 确认编码器不会把 PID 变成正反馈 | 发 `C` 退出 → `S150` | `act` 为正且往 150 爬；若是负值 → **对调编码器黄/绿** |
| **3 闭环** | 看超调 / 静差 | `S80`，打开 VOFA 连串口 | 上升 ≤50 ms、静差 ≤5%、无明显振荡 |

> 标定时 PWM 被强制为 0（滑行），电机绕组不会阻碍手转。**计数是 4 倍频后的原始值**，
> 不折算减速比 —— 所以手转的是**输出轴**（带轮子那端）10 圈，不是电机本体。
>
> 第 2 步前确认 `SPEED_LOOP_OUT_MAX` 是保守值（如 300）；第 3 步跑通后再放到 1000。
> 触发故障（OLED 显示 `FAULT xxx`）后发 `X` 可清除，**不用复位单片机**。

## 2. 引脚（唯一真源）

| 引脚 | 用途 | 关键参数 |
|---|---|---|
| PA8 | 电机 PWM | TIM1_CH1，PSC 0 / ARR 3599 → **20 kHz**，Label `MOTOR_PWM` |
| PA4 / PA5 | 方向 AIN1/AIN2 | 推挽输出，初始 Low，Label `AIN1/AIN2` |
| PA6 / PA7 | 编码器 A/B | TIM3 **TI1 and TI2**（4 倍频），Filter 6，Pull-up，Label `ENC_A/B` |
| PA9 / PA10 | USART1 TX/RX | 115200 8N1，**要勾 USART1 全局中断**（抢占 2）|
| PB8 / PB9 | OLED SCL/SDA | 软件 I²C，开漏 + 初始 High，Label `OLED_SCL/SDA` |
| PC13 | 板载 LED | **低电平点亮**，Label `LED` |
| PA13 / PA14 | SWD | SYS → Debug = **Serial Wire**（选 Disable 会锁芯片）|
| PD0 / PD1 | 8 MHz 晶振 | RCC → HSE = Crystal |

### 2.1 电机接线（TB6612 → 电机，MCU → TB6612）

**功率（11.1 V）和逻辑（3.3 V）只在 TB6612 上相遇**，不要在面包板上把它们接一起：

```
电池 + ─(开关)─► VM    ┐
电池 − ─────────► GND   ├─ TB6612 ─► AO1/AO2 ─► 电机 红/白
开发板 3.3V ────► VCC   ┘

PA8  ───────────► PWMA        (20 kHz，占空比 = 转速)
PA4 / PA5 ──────► AIN1 / AIN2 (方向)
PA6 / PA7 ◄────── 编码器 黄 / 绿 (A / B 相)
编码器 蓝 ──────► 3.3V
编码器 黑 ──────► GND（与电池 − 只在一点相连）
```

**TB6612（HW-048 或同类的 16 孔模块）**

| 模块引脚 | 接到 | 说明 |
|---|---|---|
| `VM` | 电池 +（经开关） | 模块标 **5~13.5 V**；3S 满电 12.6 V 可以，**4S 绝对不行** |
| `VCC` | 开发板 3.3 V | 逻辑电源 2.7~5.5 V |
| `GND`（3 个） | 公共地 | 内部三个相通，接一个就够 |
| `PWMA` | PA8 | 占空比 → 转速（`MOTOR_SetDuty(‰)`）|
| `AIN1` / `AIN2` | PA4 / PA5 | `1/0` 正转，`0/1` 反转，`0/0` 滑行，`1/1` 刹车 |
| `AO1` / `AO2` | 电机 **红 / 白** | 对调 = 转向相反（见下方说明）|
| `STBY` | **3.3 V（硬件拉高）** | **悬空 = 待机，电机一点反应都没有**。本工程 `MOTOR_USE_STBY=0` 的含义是「**不用 GPIO 管它，由硬件拉高**」，所以这孔必须接 3.3 V，不能空着。若你的板把该孔标成 `NC`（HW-048 某些变种，芯片内部已使能），那就悬空 |
| `BO1` `BO2` `BIN1` `BIN2` `PWMB` | 不接 | 单电机；第二路以后再说 |

**电机 JGB37-520（6 根线，同一个 PH2.0 插头，逐根对）**

| 线色 | 是什么 | 接到 |
|---|---|---|
| 红 | **电机功率 +** | TB6612 `AO1` |
| 白 | **电机功率 −** | TB6612 `AO2` |
| 蓝 | 编码器电源 | **3.3 V**（与 MCU 同电平）|
| 黑 | 编码器地 | **GND，直接回开发板**，别串进电机电流回路 |
| 黄 | 编码器 A 相 | PA6 |
| 绿 | 编码器 B 相 | PA7 |

**四条红线**

1. **蓝线只能 3.3 V**（3.3 / 5 V 都行，选 3.3 省得电平不匹配）；接 11.1 V 当场烧霍尔。
2. **红/白是电机功率线，不是给板子供电的**。6 根线在同一个插头上，这是最容易插错的地方。
3. **`VM` 和 `VCC` 不能互换**：把 11.1 V 灌到 `VCC` 会烧驱动芯片。
4. **`STBY` 别忘了拉高**（已拉高就不用管）。它控制的是整个驱动输出：悬空时 `PWMA` 给再多占空比，`AO1/AO2` 也是死的 —— 现象和“驱动板坏了”一模一样，但万用表量 `VM/VCC` 全正常。

> **想把 STBY 交给软件控制？**（急停时直接关输出，比 coast / brake 更彻底）
> 把 `STBY` 接到一个空闲 GPIO（**别用 PA6/PA7**）→ CubeMX 里配成 Output Push-Pull、User Label 设成 `STBY`
> → 根 `CMakeLists.txt` 加 `-DMOTOR_USE_STBY=1`。
> ⚠️ `motor.h:165` 有硬编码兜底：设了 `1` 但没定义 `STBY_Pin` 宏时，它会回退到 **PA6** —— 那正是编码器 A 相，
> 驱动会把测速脚当 GPIO 写电平，**测速直接废**。所以「`=1`」和「Label 叫 `STBY`」必须成对出现。

**上电验序（每步都有判据，别跳步）**

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 | **先不接电机**，只接电池 + 3.3 V | 万用表：`VM` ≈ 电池电压（12 V 左右）、`VCC` = 3.3 V、**`STBY` = 3.3 V** |
| 2 | 电机**架空**（拆轮或垫起），串口发 `S40` | 慢速转动；`?` 回的 `out` ≈ **108**（单位 ‰）|
| 3 | 发 `S200`，再发 `S-200` | 两方向都能转；不转 / 反过来见下方说明 |

> 闭环下输出 = **前馈 `Kv×target` + PID 修正**，所以起步时误差大、输出会比前馈高不少
> （`S80` 起步甚至顶到 1000‰ 饱和 —— 这正是 50ms 上升时间的来源）。
> **第一次上电只给 `S40` 左右**，手放在电池开关上。
>
> ⚠️ **驱动里没有「方向反转」的宏**（`MOTOR_AIN_ACTIVE_HIGH` 是给反相逻辑板用的，不是给接线接反用的）。
> 转向不对 → **对调 `AO1`/`AO2`（或红/白两根）**；编码器计数方向不对 → **对调黄/绿**。都在线上解决，别改代码。

## 3. 供电（三条就够）

```
3S 电池 ──(开关)── TB6612 VM          ← 只有电机功率；11.1 V 不上面包板
开发板 3.3V ──┬── TB6612 VCC          ← 逻辑
              ├── 编码器 蓝线（霍尔）
              └── OLED
```

- `VM` 只能 2.5~13.5 V（满电 12.6 V 可以，**4S 绝对不行**）；`VCC` 2.7~5.5 V。
- **板子 USB 和 ST-Link 3V3 二选一**（3.3 V 排针直连 MCU，两个源会倒灌）。
- 面包板：功率地（电池−/TB6612 GND）与逻辑地分段，**只在一点相连**；830 孔板两条电源轨中间通常是断的。

接线明细（TB6612 每个孔、电机 6 根线、上电验序）见 **§2.1**。
只有一条铁律现在还值得重复：**编码器蓝线只能 3.3 V**，接 11.1 V 会烧霍尔。

## 6. 要调的东西只有一处

`App/speed-loop/speed-loop.h` 顶部：

```c
#define SPEED_LOOP_KV       4.15f   /* 前馈 ‰/rpm（2026-10-22 自动调参：3.75 → 4.15）*/
#define SPEED_LOOP_KP       14.0f   /* 2026-10-22 自动调参：10 → 14（再大就超调/振荡）*/
#define SPEED_LOOP_KI        5.0f
#define SPEED_LOOP_KD        0.0f   /* 速度环不用 D（编码器量化噪声）*/
#define SPEED_LOOP_OUT_MAX 1000.0f  /* 满量程：50ms 靠的就是起步饱和 */
#define SPEED_LOOP_INTEG_MAX 40.0f  /* I 项上限 = 5×40 = 200‰ */

/* 编码器量化极限环抑制：稳态对 P 项加 5 rpm 死区（≈0.55 计数）*/
#define SPEED_LOOP_DEADBAND_RPM      5.0f
#define SPEED_LOOP_DEADBAND_DELAY_MS 300U   /* 目标变化后 300 ms 内不死区（保上升时间）*/
```

改完 `Ctrl+Alt+F` 重烧，一轮 ≈ 10 秒。调参记录写 `../notes/tuning-log.md`。

**不想手调了**（2026-10-22 起）—— `../tools/pid_autotune.py` 会自动搜参：
它每次只改一个数、跑 80/200 rpm 两个阶跃、算四项指标打分，不改善就回滚，
全程留档（逐帧 CSV + 每轮结论）。真机必须显式 `--live --i-own-the-rig`：

```bash
cd ~/stm32/PID
python3 tools/pid_autotune.py --verify      --live --i-own-the-rig --rpm 80,200 --repeat 3  # 只测不搜
python3 tools/pid_autotune.py               --live --i-own-the-rig --rpm 80,200 --trials 14 # 自动搜参
python3 tools/pid_autotune.py --disturbance --live --i-own-the-rig --rpm 150               # 扰动恢复（需手压）
```

## 8. 别踩这五条

1. **CubeMX 勾 `USART1 global interrupt`（抢占 2）** —— 不勾，串口一收数据整机卡死（弱符号死循环）。
2. `GENERATE CODE` 之前改动不落盘（标题栏有 `*`）；AF 脚的 Pull/速度在 TIM 的 `GPIO Settings` 里，不在 `gpio.c`。
3. F1 的 GPIO 只有 `Low`/`Medium`/`High`，没有 `Very High`。
4. TIM2 `Counter Period` 默认 65535（=6.5 s），必须是 49；TIM3 必须 `Encoder Mode TI1 and TI2`（选 `TI1` 就少一半）。
5. 烧录报端口占用：先 `pgrep -a -x openocd` 确认是残留再杀（无差别杀会让 ST-Link 卡死，得拔插 USB）。

## 9. 信息从哪来（调试时看什么）

### 9.1 六个渠道，各自能给什么

| 渠道 | 需要什么 | 能给的信息 | 刷新率 | 什么时候用 |
|---|---|---|---|---|
| **OLED** | 什么都不用（脱机） | 目标/实际/输出/增益、故障名、标定计数 | 10 Hz | 接不上电脑时；上电后的第一眼 |
| **串口文本** | USB-TTL + `picocom` | 精确数值 + 串口健康度（`rx`/`err`） | 按需（发 `?`）| 要看准确数字；怀疑串口/命令没生效 |
| **VOFA+**（`V`）| USB-TTL + VOFA+ | 100 Hz 三通道曲线 → **上升时间/超调只能这样拿** | 100 Hz | 调参、报指标、扰动实验 |
| **F5 调试器** | ST-Link | `g_pid_*` 实时改、寄存器、外设视图、断点 | 停止时 | 调参（免重烧）、查变量被谁改了 |
| **编译输出** | — | Flash/RAM 占用、错误、警告 | 每次编译 | 改完代码的第一道关 |
| **`nm` / 单测** | — | 符号是否真的链进去、纯逻辑对不对 | 每条命令 | 怀疑"代码根本没被编进去"时 |

### 9.2 按问题索引（最常用）

| 我想知道… | 去哪看 | 具体判据 |
|---|---|---|
| 电机现在转多快？ | OLED 行 2 / `?` | `ACT 147 rpm` / `act=147` |
| 目标设进去了吗？ | OLED 行 1 / 串口回显 | `TGT 150` 且回显 `TGT 150  OUT 108` |
| 输出多大？ | OLED 行 3 / `?` | `OUT 218 pcm`（‰，218 = 21.8%）|

### 9.3 各渠道的实际用法

**OLED —— 上电第一眼**

```
TGT   80 rpm      目标
ACT   79 rpm      实际（开环时显示 "ACT   --  open"）
OUT  218 pcm      占空比 ‰
KP 3 KI 30        增益；有故障时变 "FAULT NO_PULSE"
```

标定模式（发 `C`）改成四行：`CALIB (C=exit)` / `ENC 13186` / `REV 9.9` / `turn 10 revs` → **逐行含义见 §9.4**。

> 数字都是 `(int)(x + 0.5f)`，所以 79.6 显示成 80 —— **别把 `TGT 80 / ACT 79` 当成有静差**。

**串口文本 —— 要准确数字时**

```bash
picocom -b 115200 /dev/ttyUSB0      # 退出：Ctrl-A 然后 Ctrl-X
```

发 `?` 回一行（标定模式下多回一行）：

```
tgt=80 act=79 out=218 kp=3 ki=30 tick=48210 rx=57 err=0
CALIB enc=13186 revx10=99              ← 只在标定模式出现
```

| 字段 | 含义 | 健康值 |
|---|---|---|
| `tick` | 5 ms 计数 | 每秒 +200，**不涨 = 中断没进** |
| `rx` | 收到的字节数 | 敲 `?` 一次 +2 左右；不涨 = 串口收不到 |
| `err` | 串口错误计数（ORE 等）| 应该一直是 **0** |

**VOFA+ —— 唯一能拿指标的路**

波形流**上电默认开**（如果之前用 `V` 关过，再发一次 `V` 打开）。VOFA+ 选 **JustFloat**、3 通道：

```
通道 0 = target_rpm     通道 1 = actual_rpm     通道 2 = out_permille
```

用途：上升时间、超调量、扰动恢复——**这三个指标 OLED 和 `?` 都拿不到**（OLED 10 Hz、`?` 得手敲，都错过了 50 ms 的过程）。

**F5 调试器 —— 调参不用重烧**

```
变量 → Globals → g_pid_kp / g_pid_ki / g_pid_kd / g_pid_kv
改完按「继续」，下一拍（5 ms）生效，OLED 的 KP/KI 立刻跟着变
```

> ⚠️ 断点停下时**电机保持最后的输出**。要么架空，要么先发 `S0` 再按 F5。
> 调试器改的是 RAM，**复位就回到宏的初值**。

**编译输出 —— 每次都看**

```
RAM:   3544 B / 20 KB  17.30%
FLASH: 30120 B / 64 KB  45.96%
```

Flash 突然涨几千字节、或出现 `warning`，都要先弄清楚再烧。

**`nm` —— 怀疑"代码没编进去"时**

```bash
arm-none-eabi-nm build/Debug/Pid.elf | grep -E " T (SpeedLoop_Tick|MOTOR_ENC_UpdateSpeed|TIM2_IRQHandler)$"
```

必须是 **`T`**。是 `W` = 还是启动文件的弱符号死循环桩（CubeMX 没配中断）；什么都没有 = 被 gc-sections 丢了。

### 9.4 标定模式（`C`）读数详解

发 `C` 进标定：PWM 强制 0（电机滑行，手能自由转）、不跑 PID、只累计计数。四行：

```
CALIB  (C=exit)    提示：再按一次 C 退出
ENC    13186       累计的原始计数（硬数据）
REV 9.9             = ENC ÷ 1320，相当于"转了几圈"（换算值）
 turn 10 revs       提示：手转 10 圈
```

| | `ENC` | `REV` |
|---|---|---|
| 是什么 | **原始观测值** | **按 1320 换算的结果** |
| 来源 | 硬件计数，直接读 | `ENC ÷ 1320` |
| 用途 | ⭐ **验证 1320 只能用这个** | 省心算，扫一眼大概几圈 |

**⚠️ 逻辑陷阱：`REV ≈ 10.0` 不能证明 1320 是对的** —— `REV` 本身是拿 1320 除出来的，
这是循环论证（用答案验证答案）。正确算法只有一条：

```
真实 counts/圈 = ENC 总数 ÷ 人眼数的圈数

例：ENC=13186，你数了 10 圈
      → 13186 / 10 = 1318.6  ≈ 1320   ✅ 成立
      → 若得 1400         ❌ 改 MOTOR_ENC_PPR / MOTOR_ENC_GEAR_RATIO 重烧
```

所以 `turn 10 revs` 那行的重点在**“你自己数圈数”**，不是信 `REV`。

**`?` 里的那一行**

```
CALIB enc=13186 revx10=99
```

| 字段 | 含义 |
|---|---|
| `enc` | 同 `ENC`，原始计数 |
| `revx10` | **REV × 10**（= `enc × 10 / 1320`）。`revx10=100` 正好 10 圈 |

用 ×10 整数是为了避开 `printf` 浮点支持（加 `-u _printf_float` 不值得）。

**四个实操细节**

1. **小角度转不动 `REV` 要看 `ENC`**：`REV` 只留 1 位小数，`ENC=131` 时还显示 `0.0`，到 132 才变 `0.1`。
2. **正转 `ENC` 变大，反转变小（甚至负值）**：编码器计数是有符号的。标定时朝一个方向转满 10 圈，来回摆不影响，
   看的是**净计数**（别让电机本体跟着甩）。
3. **每次进 `C` 都清零**（`SpeedLoop_SetCalib()` 里 `s_enc_total = 0`）："转 5 圈→退出→再进→转 5 圈"是 5 圈，不是 10 圈。
   **10 圈要一口气转完。**
4. **`enc_total` 只给标定看，不参与控制**：控制用的是每拍的 `MOTOR_ENC_UpdateSpeed()` 瞬时转速，两套数独立。

### 9.5 故障名对照

故障同时出现在 OLED 行 4 和触发了保护之后（此时 `OUT` 被强制 0，电机断电）。**发 `X` 可清除，不用复位单片机**。

| 名字 | 含义 | 第一件事 |
|---|---|---|
| `ENC_DIR` | 给正目标、转速持续为负（>100 ms）| 对调编码器**黄/绿** |
| `NO_PULSE` | 要它转但**转速绝对值 < 3 rpm** 持续 200 ms | 查编码器 4 根线、`C` 模式看 `ENC` 动不动 |
| `STALL` | 输出 > 0.85×`OUT_MAX` 但转速上不去 500 ms | 机械卡住？目标太高？|

## 10. PID 基础、参数作用、程序设计思路

> 这一节是**原理 + 为什么代码这么写**，穿插本项目实测数字。
> 答辩被问"为什么这么配"时，答案基本都在这几张表里；现场报数用 §7 和 §10.8。

### 10.1 一句话原理

**闭环 = 用"差多少"决定"给多少"，并且每 5 ms 重新算一次。**

```
   目标 rpm ──►( − )──► 误差 e ──► PID ──► + 前馈 ──► 限幅 ──► PWM 占空比 ──► 电机 ──► 转速
      ▲            ▲                  │                                        │
      │            └── 实测 rpm ◄── 换算(×9.09) ◄── 编码器计数差 ◄────────────┘
      └── 串口 S200 / 自动阶跃 / 上位机
```

三句话说清：

1. **P 看"现在差多少"** —— 差得多就给得多。
2. **I 看"过去一直差多少"** —— 只要还有一点静差，它就把输出一点点往上推，直到误差为 0。
3. **D 看"误差在变快还是变慢"** —— 提前刹车，抑制超调。

本工程额外加了一项 **前馈（Kv×目标）**：它不在反馈环里，作用是把"稳态大概需要多少占空比"**提前给到位**，
让 PID 只需要修小误差。这是本机做到 <50 ms 的主要原因（见 §10.6）。

### 10.2 四个参数各自管什么（含"调大调小会怎样"）

| 参数 | 物理含义 | 调大 | 调小 | 本机值 | 怎么看出来 |
|---|---|---|---|---|---|
| **Kp** | 每 1 rpm 误差给多少 ‰ | 响应快，但**超调、振荡**，最后变成"嗡"的极限环 | 慢，追不上，静差靠 I 慢慢补 | **14** | 阶跃前期斜率 / 峰值 |
| **Ki** | 误差累积多快 → 消静差 | 静差消得快，但**低频摆**（0.5~2 s 周期） | 静差消得慢，长时间不到目标 | **5** | 稳态残差 / 尾巴慢摆 |
| **Kd** | 按"误差变化率"提前刹车 | 抑超调，但**放大测量噪声**，高频抖动 | 超调大一些 | **0** | 稳态毛刺（越大越抖） |
| **Kv** | 前馈：1 rpm 稳态需要多少 ‰ | 起步更猛、更快，过头则超调 | 起步没劲，全靠 Kp 硬拉，慢且易饱和 | **4.15** | 阶跃起点那一下的抬升 |

**Kd 为什么是 0（这题一定会问）**：速度环的测量是"5 ms 内的编码器计数差"，
**1 个计数 = 9.09 rpm**，本身就是一个 9 rpm 量级的量化台阶。
D 项对变化率最敏感，会把这个台阶放大成输出抖动（听觉上是嗡嗡声，VOFA 上是毛刺）。
位置环才需要 D；**速度环用 PI 就够，抗超调靠前馈标定 + 条件积分**。

**Kp=14 的量化账**（答辩可以直接算给评委看）：

```
1 计数 = 9.09 rpm   →   P 项跳变 = 9.09 × 14 ≈ 127 ‰
```

也就是说误差只要跳一个计数，输出就跳 127‰ —— 这就是"极限环"的来源。
对策不是把 Kp 砍小（会牺牲上升时间），而是**稳态对 P 项加 5 rpm 死区**（§10.5 第 6 条）。

### 10.3 用的是「位置式 PI + 条件积分」，为什么

| 选择 | 备选 | 为什么选它 |
|---|---|---|
| **位置式**（直接算占空比） | 增量式（算"这次多加多少"） | 位置式的输出就是"绝对占空比"，跟前馈、限幅、`MOTOR_SetDuty(‰)` 天然对齐；增量式更适合步进/积分器本身是执行器的场合 |
| **条件积分**（饱和时冻结积分） | 只靠积分限幅 | 输出顶到 1000‰ 时误差还很大，若继续累加，退饱和后积分要很久才吐出来 → **大超调**。冻结之后一退饱和就能立刻响应 |
| **积分限幅 40**（I 项最多 200‰） | 不限制 | 万一堵转/追不上，积分不会堆到天文数字；200‰ ≈ 输出上限的 20%，够消静差 |
| **微分作用在测量值**（`-Kd·d(meas)/dt`） | 作用在误差上 | 目标阶跃瞬间 `de/dt` 是无穷大 → 会产生一个巨大的"微分冲击"。用测量值就没有这个问题 |
| **输出限幅 ±1000‰** | 不限 | 保护电机和驱动器（TB6612 连续 1 A）；也正因为会饱和，才必须配条件积分 |

代码就三处（`App/pid/pid.c`）：

```c
err = target - meas;
if (没饱和 || (顶在上限 && err<0) || (顶在下限 && err>0))  integral += err*dt;   // 条件积分
d_filt += alpha * (raw_d - d_filt);                                        // 测量值微分 + 一阶低通
out = kp*err + ki*integral - kd*d_filt;   out = clamp(out, out_max);        // 三项相加 + 限幅
```

### 10.4 程序结构：四层，各管一件事

| 层 | 文件 | 在哪儿跑 | 职责 | 允许 include HAL？ |
|---|---|---|---|---|
| 调度/闭环 | `App/speed-loop/speed-loop.c` | **TIM2 中断，5 ms** | 读编码器差 → 算 rpm → PID → 前馈+限幅 → 写 PWM；三条保护 | ✅ |
| 纯控制律 | `App/pid/pid.c` | 被上面调用（也在 PC 上跑） | 只有算术，无硬件 | ❌ **故意不 include** |
| 命令解析 | `App/cmd/cmd.c` | 中断喂字节 + 主循环取结果 | 手写状态机，不解析浮点、不用 `sscanf` | ❌ |
| 遥测/显示 | `App/vofa/`、`App/ui/` | 主循环 | JustFloat 组帧 / OLED 四行 | `ui` 用驱动，`vofa` 不用 |
| 外设驱动 | `Components/*` | 被上层调用 | PWM/方向/编码器、软件 I²C 屏 | ✅ |

**一个 5 ms 周期里到底发生了什么**（顺序固定，不能换）：

```
TIM2 更新中断
 ├─ ① 目标：从 cmd 取（自动阶跃也走同一个入口，保证"目标只有一个来源"）
 ├─ ② 测速：TIM3 CNT 差值（int16，处理 16 位回绕）→ ×9.09 → rpm
 ├─ ③ PID：误差 → 条件积分 → 微分低通 → 三项相加 → 限幅
 ├─ ④ 前馈 + 总限幅：duty = Kv×目标 + pid_out，再 clamp 到 ±1000‰
 └─ ⑤ 写 CCR（PWM）+ 存遥测快照；保护判断也在这里
主循环（不在中断里）：串口收命令、'?' 应答、VOFA 200 Hz 发送、OLED 每次画一行
```

为什么要这样切：**中断里只允许"确定耗时"的活**。浮点乘加、几个 `if` 是确定的；
`printf`、刷 OLED、`HAL_Delay` 是几十毫秒级的阻塞，放进 5 ms 中断里会直接丢拍。

### 10.5 六个设计决定（都是被坑出来的，答辩可展开）

1. **控制律与硬件解耦**：`pid.c` / `cmd.c` / `vofa.c` 不 include HAL
   → 能在 PC 上直接 `gcc` 编了跑单测（`tests/test_pid.c` 20 项、`test_cmd.c` 43 项、`test_vofa.c` 6 项）。
   改算法不用烧板子，这是"调参有依据"的底气。
2. **目标只有一个来源**：串口 `S` 命令、自动阶跃都写进 `CMD_SetTargetRpm()`。
   否则"自动阶跃"和"手打 S200"会互相打架，曲线对不上。
3. **命令解析用手写状态机，不用 `sscanf`**：Flash 小、溢出可控（灌 100 位数字也不会崩）、
   而且**整行收齐才生效**——不会出现"收到 `S1` 就把目标改成 1"的半截执行。
4. **发送不走 `HAL_UART_Transmit`，直写寄存器**：HAL 的发送和 `Receive_IT` **共用 `huart->Lock`**，
   主循环发数据时中断里重新武装接收会拿到 `HAL_BUSY`，**接收就永久关掉**（症状：发过一次就再也不响应，只能复位）。
5. **遥测用"结构体快照"**：中断只写 `s_tel`，主循环拷一份去发/显示。
   这样 ISR 永远不被串口速率拖慢，VOFA 掉帧也不影响控制。
6. **抗量化极限环：稳态才开死区**。`PID_UpdateEx(..., p_deadband)` 只压 P 项，
   积分仍看真实误差（否则会留静差）；**目标变化后 300 ms 内死区为 0**，
   所以阶跃全程有 P（上升时间不受影响），进稳态后 out 从 460~720‰ 的摆动收敛到 536±1‰。

### 10.6 为什么必须加前馈（实测对比）

只靠大 Kp 时，起步瞬间输出就顶到 1000‰（饱和），条件积分把积分冻住；
退出饱和时积分还很小，最后几个百分点只能靠 Kp 慢慢爬 —— **结果是 Kp 越大越慢**。
前馈把稳态占空比提前给到位（200 rpm 时 `Kv×200 ≈ 830‰`），PID 只修剩下的零头。

| 方案 | 现象 | 上升时间 |
|---|---|---|
| Kp=3、Ki=30，无前馈 〔仿真〕 | 起步没劲 | 320 ms |
| Kp=20，无前馈 〔仿真〕 | 饱和 → 冻结积分 → 爬 | 690 ms（**更慢**）|
| Kp=80，无前馈 〔仿真〕 | 快到近振荡 | 45 ms，但超调 13.5% |
| **前馈 Kv=4.15 + Kp=14、Ki=5 〔真机〕** | 起步就接近稳态占空比 | **33~39 ms** |

〔仿真〕= 一阶惯性模型（T=80 ms），用来证明"Kp 越大反而越慢"这个反直觉结论；
〔真机〕= 80 rpm 阶跃实测。完整过程见 `../notes/tuning-log.md`，真机复现用 `pidtune verify`。

### 10.7 指标怎么量（别自己发明定义）

| 指标 | 定义 | 本机实测 |
|---|---|---|
| 上升时间 | 首次进入 **±5% 带**的时刻 − 目标跳变时刻 | 80 rpm：**33~39 ms**；200 rpm：76~78 ms |
| 超调 | (峰值 − 目标) / 目标 | 2.3~6.1%（受量化影响，见下） |
| 静差 | 最后 1 s 内 (目标 − 实际) 均值 / 目标 | **−0.3 ~ −1.9%** |
| 扰动恢复 | 撤除外力后重新进 ±5% 带并保持 300 ms | 见 `pidtune disturb` |

⚠️ **量化下限**：5 ms 窗口下 1 计数 = 9.09 rpm。目标是 80 rpm 时，1 个计数就是 **11%**，
所以"超调 6%"里有一部分是读数台阶，不是真的冲过头（这就是为什么测量要平滑、要 200 Hz 遥测）。
150 rpm 时 1 计数 = 6%；200 rpm 时 4.5%。**报数字时要连"量化下限"一起讲，否则容易被追问。**

### 10.8 现场常被问的 7 个问题（短答）

| 问题 | 一句话回答 |
|---|---|
| 为什么不用 D？ | 速度环测量是"5 ms 计数差"，1 计数 = 9.09 rpm，D 会放大这个台阶成抖动；PI 足够 |
| 为什么控制周期 5 ms，不用 1 ms？ | 1 ms 时 1 计数 = 45 rpm，量化误差比信号还大；5 ms 时 9.09 rpm，且 50 ms 指标有 10 个采样点 |
| 为什么要前馈？ | 大 Kp 一饱和就冻结积分，反而更慢；前馈直接给稳态占空比，PID 只修小误差 |
| 输出都顶到 1000‰ 了还叫"闭环"吗？ | 叫。饱和只是**加速阶段**的手段，进入 ±5% 带之前就退饱和了，稳态只用到 300~830‰ |
| 积分饱和怎么防？ | 条件积分（饱和且误差同向时冻结）+ 积分限幅 40（I 项 ≤200‰）+ 输出限幅 |
| 为什么 200 rpm 做不到 50 ms？ | 满占空比可达 ≈267 rpm、机械时间常数 ≈111 ms：`267×(1−e^(−50/111)) ≈ 97 rpm`。**物理上限，不是调参问题** |
| 参数是不是凑出来的？ | 有 20+43+6 项单测、两轮自动调参记录（`notes/autotune/`）、标定流程和量化误差分析 |

### 10.9 想自己再动参数时

| 目标 | 动哪个 | 别动哪个 |
|---|---|---|
| 更快（牺牲超调） | Kv +5~10%，或 Kp +2 | 别一次加两个 |
| 更稳（接受慢一点） | Kp −2 | 别把 I 加大去换速度 |
| 静差大 | Ki ×1.5（先确认不是测速标定错、不是电池没电） | 别用加大 Kp 去消静差 |
| 稳态嗡嗡/毛刺 | 死区 5→6 rpm；或 Kv 回调 | 别用 Kd 去压（会更抖） |
| 换电池后 | **只重标 Kv**（`pidtune kv`），Kp/Ki 不用动 | 别重新手调一遍 |

改完的固化流程：串口验证（`pidtune verify`）→ 写回 `App/speed-loop/speed-loop.h` 的宏 → 重烧。
串口改的值**复位就丢**，这是故意的（防手滑）。
