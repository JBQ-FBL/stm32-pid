# Pid — STM32 直流电机速度闭环

使用 **STM32F103C8T6 + TB6612 + JGB37-520 编码器电机**实现速度控制：每 5 ms 运行一次 PI + 前馈，通过 VOFA+ 显示曲线、OLED 显示状态。

当前调参选择更小的超调和稳态波动，代价是稍慢的首次到达目标时间。**80 rpm 三次复测均小于 50 ms；150、200 rpm 尚未达到 50 ms。**

本文当前参数与实测对应已烧录、验收的提交 `140cffb`（2026-10-23）；后续源码修改需重新构建和验证。

## 当前参数与实测

参数集中在 [`App/speed-loop/speed-loop.h`](App/speed-loop/speed-loop.h)：

| 参数 | 当前值 | 作用 |
|---|---:|---|
| Kp | 10 | 根据当前速度误差修正输出 |
| Ki | 7 | 累积误差，减小稳态偏差 |
| Kd | 0 | 本轮使用 PI，未启用微分 |
| Kv | 3.75 ‰/rpm | 提前给出接近稳态所需的占空比 |
| 输出限幅 | ±1000‰ | 对应正反向 0–100% 占空比 |
| 积分状态限幅 | ±40 rpm·s | 当前 I 项上限为 `7 × 40 = 280‰` |

同一硬件、负载与三点编码器平均配置下，各工作点独立复测三次，均值如下：

| 目标转速 | 响应时间 | 超调 | 静差 | 稳态纹波（峰峰值） |
|---|---:|---:|---:|---:|
| 80 rpm | 46.57 ms | 7.32% | +0.28% | 2.02 rpm |
| 150 rpm | 66.59 ms | 4.60% | +0.05% | 3.03 rpm |
| 200 rpm | 91.59 ms | 3.54% | −0.72% | 4.71 rpm |

与旧参数 `Kp=14、Ki=5、Kd=0、Kv=4.15` 相比，80 rpm 平均超调由 **17.0% 降到 7.3%**，稳态纹波由 **3.70 降到 2.02 rpm**；平均响应由 **39.7 增加到 46.6 ms**。新响应范围为 **43.6–48.1 ms**，曲线更平稳，但不是每项速度指标都更快。

测量口径：响应为首次进入目标的 **±5% 带**，超调为峰值超过目标的比例，静差为末 1 秒的 `(目标−实际)/目标`；负静差表示实际转速偏高。统计使用额外的三点分析平滑，原始指标另存于 JSON。串口时间来自接收块插值，**不是 MCU 采样时间戳**，VOFA 上的单点峰值可能高于表中结果。首次进带也不等于从此不再离开误差带。

完整对比、候选筛选和原始数据见 [`tests/TUNING.md`](tests/TUNING.md)。外力扰动恢复仍待人工测试，不能据上述阶跃成绩推断。

## 快速使用

### VOFA+ 看曲线

1. 确认电机可自由转动，电机电源、编码器和公共地已连接。
2. VOFA+ 选择 CH340 对应串口，设置 **115200、8N1、JustFloat、3 通道**；同一串口只由一个程序使用。
3. 波形流上电默认开启，自动阶跃默认关闭。单独发送 `S80` 并加换行，观察目标和实际转速；发送 `X` 停止。
4. 需要循环演示时发送 `A`：从启用时刻等待 2 秒，以 150 rpm 保持 3 秒，再回零，10 秒一周期。再次发送 `A` 停止；`S` 或 `X` 也会退出自动阶跃。

| 通道 | 数据 | 单位 |
|---|---|---|
| 0 | 目标转速 | rpm |
| 1 | 编码器测得的实际转速 | rpm |
| 2 | 最终控制输出，含前馈与 PID 修正 | ‰ |

波形按 5 ms 控制 tick 发送，目标为 200 帧/s。主循环若漏过旧样本，只发送最新快照，不集中补发历史数据。

### 串口命令

命令大小写均可。数值命令遇 `\n` / `\r` 执行；没有换行时，停顿 500 ms 自动结算。`X/x` 在任何解析状态下都优先急停，不等待换行。

| 命令示例 | 行为 |
|---|---|
| `S80`、`S-80` | 设置正反向目标，范围限制为 ±333 rpm；有效非零目标可解除停止锁存 |
| `S0` | 停止并保持零输出，不清除已有故障 |
| `X` | 关闭自动阶跃、清故障并锁存停止；恢复运行需重新发送非零 `S` 或显式开启 `A` |
| `A` | 开关自动阶跃；关闭时停止 |
| `V` | 开关二进制波形流 |
| `C` | 进出编码器标定；进入和退出都停止，退出后需重新给速 |
| `KP10`、`KI7`、`KD0`、`KV3.75` | 修改 RAM 中的增益或前馈；每次只发送一条 |
| `?` | 查询目标、实际、输出、参数和诊断计数 |

文本终端需要先发 `V` 关闭波形，否则二进制数据看起来像乱码。波形开启时，普通操作不自动回显；显式 `?` 仍返回文本，可能短暂打断波形发送，不要在性能采集窗口内频繁查询。

状态行示例：

```text
tgt=80 act=80 out=300 kp=10.0 ki=7.0 kd=0.00 kv=3.8 tick=12345 rx=42 err=0 f=0 miss=0
```

- `tick`：控制周期计数，正常约每秒增加 200；`rx`：已收到的字节数。
- `err`：UART 错误累计数；增加时检查串口链路和写入节奏。
- `f`：故障码，0 正常、1 方向异常、2 无脉冲、3 堵转。
- `miss`：波形开启期间漏过的控制 tick 数，不检测 USB/电脑端丢包；查询自身也可能使它增加。
- `kv` 只打印一位小数，**3.75 显示成 3.8**，不代表固化参数被改成 3.8。

终端行尾应发送真正的 `\n` / `\r`；将行尾误设为字母 `LF` 会使 `S80` 变成非法的 `S80LF`。

### OLED 与实时改参

OLED 显示目标、实际、输出和参数；故障时第四行显示故障名。每秒生成显示内容，只分块写入变化字符，**不是 5 ms 内整屏刷新**。初始化失败或运行中无应答后暂停显示，复位重试。

VOFA+ 滑块可绑定 `KP%f`、`KI%f`、`KD%f`、`KV%f`，并添加换行，不需要额外的包尾字符。固件增益上限为 Kp≤100、Ki≤200、Kd≤50、Kv≤20，这些是钳位边界，不是推荐调参范围。

本轮曾发生批量写参回读失配，因此重新调参时应先 `X` 停机，**逐条写入、逐条用 `?` 回读**，再给速测试，避免同时快速拖动多个滑块。RAM 改参复位后会丢失；确认有效后更新头文件并重烧。

## 硬件与接线

### MCU 引脚

| 引脚 | 用途 | 配置 |
|---|---|---|
| PA8 | TB6612 PWMA | TIM1_CH1，20 kHz PWM |
| PA4 / PA5 | AIN1 / AIN2 | 推挽方向输出 |
| PA6 / PA7 | 编码器 A / B | TIM3 TI1 and TI2，四倍频，上拉，Filter 6 |
| PA9 / PA10 | USART1 TX / RX | 115200 8N1；接 USB-TTL RX / TX |
| PB8 / PB9 | OLED SCL / SDA | 软件 I²C，开漏输出 |
| PC13 | 板载 LED | 低电平点亮 |
| PA13 / PA14 | SWDIO / SWCLK | 保留 Serial Wire 调试接口 |
| PD0 / PD1 | HSE | 8 MHz 晶振 |

TIM2 每 5 ms 触发一次控制中断，抢占优先级 1；USART1 中断抢占优先级 2。引脚与外设配置以 [`Pid.ioc`](Pid.ioc) 及生成代码为准。

### 电机与供电

| 接口 | 当前接法 |
|---|---|
| TB6612 VM | 3S 电池正极，经电源开关 |
| TB6612 VCC | 开发板 3.3 V |
| TB6612 GND | 与 MCU、编码器及电池负极共地；功率回路与信号地在一点汇合 |
| TB6612 AO1 / AO2 | 电机功率线红 / 白 |
| TB6612 STBY | 本工程由硬件使能，不使用 GPIO 管理；有 STBY 引脚的模块须按其说明拉高 |
| 编码器蓝 / 黑 | 3.3 V / GND |
| 编码器黄 / 绿 | PA6 / PA7；线色仅对应当前这台电机 |
| OLED VCC / GND | 3.3 V / GND |

**VM 是电机电源，VCC 和编码器电源是逻辑电源，不能互换。**当前使用 3S 电池，满电 12.6 V；不要改用 4S。MCU 由 ST-Link 3V3 或开发板 USB 供电时二选一，避免两路电源直接并联。

`MOTOR_USE_STBY=0` 表示不由程序控制 STBY，不表示该引脚可以悬空。若改成 GPIO 管理，必须同步配置 CubeMX 标签和驱动宏，避免兜底引脚占用编码器 PA6。接线调整前先停止并断开电机供电。

接线参考：[编码器连接图](docx/编码器连接图.jpg)；模块原始资料位于 `docx/`。

### 编码器标定

配置按 `11 PPR × 四倍频 × 减速比 30 = 1320 计数/输出轴圈` 换算，但本轮没有重新完成机械十圈标定。

1. 发 `C` 进入标定，输出被强制为零，计数清零。
2. 朝同一方向手转**输出轴**正好 10 圈，查看 OLED 的 `ENC` 或发送 `?`。
3. 预期累计约 ±13200 计数；`真实每圈计数 = 净计数 / 实际圈数`。偏差明显时核对 PPR、减速比和倍频。
4. 再发 `C` 退出；此时仍保持停止，需重新给速。

标定状态附加示例：`CALIB enc=13200 revx10=100`。`REV` 与 `revx10` 都按配置的 1320 换算，不能用它们反过来证明 1320 正确；应比较人工圈数与原始计数。

## 控制设计

每个 5 ms 控制周期依次处理运行请求、读取编码器、计算 PI 与前馈、检查保护、写 PWM，并更新遥测快照。

```text
误差 e = 目标转速 − 实测转速
P 项 = 稳态死区内取 0，否则取 Kp × e
修正量 = clamp(P 项 + Ki × integral − Kd × filtered_d_measurement, −1000, +1000)
最终输出 = clamp(Kv × 目标转速 + 修正量, −1000, +1000)
```

- **P** 决定对当前误差的修正力度。此次降低 Kp，减小了超调，也略微增加响应时间。
- **I** 累积持续偏差。此次 Ki 从 5 增至 7，改善中高速静差；积分状态仍限制在 ±40。
- **D** 的实现作用于测量值，当前 Kd=0；编码器有量化台阶，启用微分可能放大噪声。
- **前馈** 提前给出接近稳态的输出，例如 80 rpm 时 `3.75 × 80 = 300‰`，再由 PI 修正。

### 测速、死区与限幅

| 配置 | 当前值及含义 |
|---|---|
| 时钟 / PWM | HSE 8 MHz → 72 MHz；`72 MHz / 3600 = 20 kHz` |
| 控制周期 | TIM2：`72 MHz / 7200 / 50 = 200 Hz` |
| 单拍转速换算 | `rpm = Δcounts × 60000 / (1320 × 5)` |
| 三点平均 | 对最近 3 拍计数取平均，15 ms 窗口；转速量化台阶约 3.03 rpm，群延迟约 5 ms |
| 稳态 P 项死区 | 目标保持 300 ms 后启用 5 rpm 死区；积分继续使用真实误差 |
| 抗饱和 | 条件积分与积分状态限幅；另对最终输出做 ±1000‰ 限幅 |

当前条件积分依据 **PID 内部输出**判断饱和，尚未把前馈叠加后的最终饱和反馈给积分器，不能称为完整的执行器抗饱和补偿。

控制在 TIM2 中断执行；UART 回调只做接收解析，主循环处理波形发送、文本查询和显示。OLED 每控制 tick 最多写 4 字节；串口和 OLED 阻塞操作不放入控制中断。

## 构建与验收

以下命令均从仓库根目录执行。需要 CMake 3.22+、Ninja 和 `arm-none-eabi-gcc`；主机测试使用 GCC，烧录使用 OpenOCD 与 ST-Link。`Drivers/` 被 Git 忽略，独立克隆后需通过 STM32CubeMX/对应固件包补齐 HAL 与 CMSIS。

### 编译与烧录

```bash
cmake -S . -B build/pid-tuned/Debug -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake -DCMAKE_BUILD_TYPE=Debug
cmake --build build/pid-tuned/Debug
```

将路径中的 `Debug` 和构建类型都换为 `Release` 可构建优化版本。确认产物后烧录并校验：

```bash
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
  -c 'program build/pid-tuned/Debug/Pid.elf verify reset exit'
```

以退出码成功且日志出现 **`Verified OK`** 为烧录成功依据。本机另有 `~/stm32/scripts/build-flash.sh` 和 VS Code 快捷任务，均不随仓库分发；使用时注意其实际选择的构建目录。修改 CubeMX 生成文件时只写 `USER CODE` 区，新增源文件和包含路径登记在根 `CMakeLists.txt`。

### 软件回归

```bash
bash tests/run_host_tests.sh
```

该命令运行 PID、命令解析、VOFA、速度环桩测试和 UI 桩测试五组回归。通过说明所覆盖逻辑符合预期，不等于实机响应达标。

### 本机真机验收

脚本需要 Python、pyserial，以及本机父目录 `../tools/` 中的 `pid_autotune.py`、`serial_probe.py`；后两者不包含在此仓库中。运行前关闭 VOFA+/其他串口工具。

```bash
# 连续性：保持停止，采集 60 秒
python3 tests/hardware_acceptance.py --mode continuity --secs 60 \
  --out build/acceptance/continuity

# 会驱动电机：80/150/200 rpm 各三次，完成或异常时停机
python3 tests/hardware_acceptance.py --mode steps --i-own-the-rig \
  --out build/acceptance/steps

# 会驱动电机：急停、反转、自动阶跃、标定进出等检查
python3 tests/hardware_acceptance.py --mode functional --i-own-the-rig \
  --out build/acceptance/functional
```

`--i-own-the-rig` 表示已确认电机可自由转动、串口独占。复现调参时采用停机逐条写参并回读的流程；不要将旧工具的批量写入结果直接当作有效试验。

已完成：Debug/Release 构建、主机回归、调参前后重复阶跃、烧录后补测与 15 项运动功能检查。仍待完成：人工外力扰动恢复、机械十圈标定，以及逻辑分析仪测量真实急停输出延迟。验收记录仅对应记录中的固件与环境。

### 波形连续性改善

下表为同条件、OLED 开启时各 60 秒的**静止采集**；时间是接收端插值估计，不是控制周期抖动测量。

| 指标 | 优化前 | 分块刷新后 |
|---|---:|---:|
| 平均帧率 | 165.05 帧/s | 200.03 帧/s |
| 最大接收间隙 | 158.74 ms | 6.18 ms |
| 超过 30 ms 的间隙 | 60 次 | 0 次 |

OLED 四字节写入 DWT 抽测约 **1.053 ms**。这是单次样本，不是最坏耗时保证；静止采样结果也不替代运行状态长时间测试。详细过程见 [`tests/VALIDATION.md`](tests/VALIDATION.md)。

## 排错与故障保护

| 现象 | 优先检查 |
|---|---|
| 文本终端全是乱码 | 默认二进制波形是否开启；发 `V` 切到文本模式，确认 115200 波特率 |
| VOFA 没有曲线 | JustFloat、3 通道、波形开关、串口是否被其他程序占用 |
| `S80` 不生效 | 命令是否带真实换行；`rx` 是否增加、`err` 是否增加；查询目标值而不是只等回显 |
| 参数读数和发送值不同 | 逐条发送、回读；注意 Kv 一位小数的显示舍入 |
| 电机不转 / 无脉冲 | 电机电源开关、VM/VCC/GND、STBY、驱动连接；再检查编码器，不能只靠改 PID |
| 正目标得到负速度 | 先 `X` 停止；核对电机与编码器方向，调整接线前断开电机供电 |
| OLED 不亮 | 3.3 V、公共地、SCL/SDA；无应答后需复位重新初始化 |
| 烧录连接失败 | ST-Link 供电和 SWD 接线；先用 `pgrep -a -x openocd` 确认占用，不盲目结束所有进程 |

故障对正反向均有效，达到条件的当拍撤销输出：

| `f` / 名称 | 条件 |
|---|---|
| 1 / `ENC_DIR` | 目标绝对值>50 rpm、测量绝对值>5 rpm，方向相反持续 100 ms；正常换向留 300 ms 过渡 |
| 2 / `NO_PULSE` | 目标绝对值>50 rpm、测量绝对值<3 rpm，持续 200 ms |
| 3 / `STALL` | 输出绝对值>850‰、测量绝对值<10 rpm，持续 500 ms |

故障锁存后先排查原因，再发 `X` 清除；清除后保持停止，需要重新给速。程序致命异常会先撤销输出再进入诊断/等待。调试断点暂停 CPU 不等于关闭 PWM，进入断点调试前先停止电机。
